# Plan 15/01 - Umbrales Dinamicos por Servidor (MIRA + ML)

Objetivo: mantener deteccion ultra-rapida con DPDK/OctoSketch y ajustar
umbrales de forma dinamica por servidor, usando el pipeline actual
de recoleccion y entrenamiento.

## 1) Estado actual
- Detector DPDK con ventanas de 5s y contadores por protocolo.
- Features protocol-specific ya disponibles (NTP/DNS/SNMP/SSDP/PortMap/NetBIOS/LDAP/MSSQL/TFTP).
- Pipeline de datos y entrenamiento descrito en `mira/stepsML_02.md` y `mira/stepsML_03.md`.
- Generador `mixed` secuencial y ponderado para validar detecciones.

## 2) Metricas a ajustar (umbrales dinamicos)
- PPS por protocolo: udp_pps, syn_pps, http_rps, icmp_pps.
- Amplificacion: dns_qps, ntp_qps, snmp_qps, ssdp_pps.
- Servicios: portmap_pps, netbios_pps, ldap_pps, mssql_pps, tftp_pps.
- Ratios: udp_tcp_ratio, syn_total_ratio, baseline_attack_ratio.
- Tamano medio de paquete: avg_pkt_size (para UDP-Lag).

## 3) Baseline por servidor
1) Capturar trafico benigno real (minimo 1-3 horas por servidor).
2) Ventanas de 5s (igual que el detector).
3) Calcular percentiles por metrica:
   - base = p99
   - alta = p99.9
4) Guardar en un JSON por servidor (ej. `thresholds_server.json`).

## 4) Ajuste dinamico
Opciones (empezar por la simple):
- EWMA: umbral_t = alpha * base + (1 - alpha) * umbral_(t-1)
- Con limites: min/max globales para evitar desactivar el detector.

Si se quiere ML:
- Regresion ligera (LightGBM) para predecir umbrales por servidor.
- Features: hora, dia, total_pps, avg_pkt_size, ratios.

Frecuencia de actualizacion:
- Cada 1-5 minutos en runtime.
- Recalibrar base semanalmente o tras cambios grandes de carga.

## 5) Logica de deteccion recomendada
- Trigger rapido: umbral dinamico superado.
- Confirmacion: si ML clasifica attack/mixed, elevar a CRITICAL.
- Si hay conflicto, mantener ANOMALY.

## 6) Validacion con lo actual
1) Generar PCAP `mixed` secuencial y ponderado.
2) Enviar en loop a 12 Gbps para 30 min.
3) Verificar que cada bloque activa su evento correspondiente.
4) Ajustar umbrales por ataque si algun evento no dispara.

## 7) Limitaciones conocidas
- Amplificacion real suele requerir respuestas; si no hay respuestas,
  los eventos pueden no disparar (DNS/NTP/SNMP/SSDP).
- Cambios de IP ranges (10.10.2.x/10.10.3.x) invalidan clasificacion.
- Umbrales absolutos sin ajuste dinamico pueden fallar en picos benignos.

## 8) Entregables
- JSON de umbrales por servidor.
- Script de recalculo de umbrales base.
- Config en detector para leer umbrales sin recompilar (opcional).
